# ربات تبدیل ویس و پاسخ‌گوی انسانی — نسخه ۷

این نسخه بر پایه نسخه ۵ ساخته شده است. فایل `requirements.txt`، نام مدل‌های پیش‌فرض در `bot.py`، مدل‌های تنظیم‌شده در ورک‌فلو و پرامپت‌های اصلی تغییر نکرده‌اند. نام مدل‌های تنظیم‌شده در کد و ورک‌فلو با هم متفاوت است؛ مقدارهای ورک‌فلو هنگام اجرای GitHub Actions بر مقدارهای پیش‌فرض کد تقدم دارند. دسترسی و پشتیبانی واقعی مدل‌ها باید با حساب و کلید شما بررسی شود.

## راه‌اندازی

۱. `BOT_TOKEN` و `GEMINI_API_KEY` را در متغیرهای محیطی یا GitHub Secrets ثبت کنید. دیگر هیچ کلید جایگزینی داخل کد وجود ندارد.

۲. برای محدودکردن دسترسی، `ALLOWED_USER_IDS` را با شناسه‌های عددی و جداشده با ویرگول تنظیم کنید. اگر خالی باشد، کاربران چت خصوصی به ربات دسترسی دارند؛ بنابراین برای استفاده خصوصی حتماً آن را تنظیم کنید. شناسه خود را با `/id` بگیرید.

۳. وابستگی‌ها و `ffmpeg` را نصب کنید، سپس `python bot.py` را اجرا کنید. در GitHub، محتویات پوشه نسخه ۷ را در ریشه مخزن قرار دهید و ورک‌فلو را از تب Actions اجرا کنید.

۴. مدل فعال را با `/settings` بررسی کنید. تنظیمات قبلی کاربر در دیتابیس نیز می‌تواند بر مقدار پیش‌فرض محیطی تقدم داشته باشد.

**امنیت مهم:** نسخه ۵ حاوی مقادیر کلیدِ پنهان‌شده در کد بود. پنهان‌سازی رمزنگاری امنیتی نیست. اگر این کلیدها واقعی بوده‌اند، توکن تلگرام و کلید گوگل را باطل و مجدداً صادر کنید. نسخه ۷ این مقادیر را ندارد.

## ده روش بهبود سرعت

۱. نگهداری نتیجه رونویسی برای فایل تکراری، با تفکیک کاربر و مدل؛ در ارسال تکراری، دانلود و درخواست مدل حذف می‌شوند.
۲. استفاده مشترک از درخواست در حال اجرای پاسخ انسانی، حتی اگر دکمه چند بار زده شود.
۳. استفاده مشترک از درخواست در حال اجرای خلاصه.
۴. استفاده مشترک از ترجمه در حال اجرا برای متن و تنظیمات یکسان.
۵. کش پایدار ترجمه، تفکیک‌شده براساس متن، مدل و سطح تفکر.
۶. انتقال عملیات سنگین‌تر دیتابیس در مسیر پیام به نخ جداگانه، برای آزادماندن حلقه پردازش تلگرام.
۷. نگهداری کش محدود و دارای زمان انقضا برای رکوردها و نگهداری اتصال SQLite و ایندکس‌های جست‌وجو.
۸. جلوگیری از تبدیل مجدد فایل‌های صوتی معمولی از جمله Ogg؛ این کار زمان پردازش را حذف می‌کند و از افت کیفیت ناشی از تبدیل مجدد جلوگیری می‌کند. استخراج صدای ویدیومسیج مانند نسخه ۵ همچنان ممکن است.
۹. ارسال درخواست جایگزین به **همان مدل و همان تنظیمات** در صورت کندی، همراه با لغو درخواست بازنده. این روش ممکن است هزینه و مصرف سهمیه را بیشتر کند و هیچ سرعت تضمین‌شده‌ای ندارد.
۱۰. کنترل همزمانی درخواست‌های هوش مصنوعی برای جلوگیری از اشباع و حفظ قابلیت پاسخ‌گویی؛ ارسال پیام وضعیت و پردازش موازی و پیش‌تولید پس‌زمینه نسخه ۵ نیز حفظ شده‌اند.

سرعت پیام اول عمدتاً به اندازه فایل، شبکه، سرور تلگرام، مدل و بار سرور گوگل وابسته است. برای اندازه‌گیری واقعی، در هر دو نسخه ورودی‌های مشابه را چند بار آزمایش کنید. با `LOG_TIMINGS=true` زمان کل هندلرهای متن و ویس، بدون ثبت متن پیام، در لاگ نوشته می‌شود. نتایج این پروژه بدون تست با توکن معتبر، افزایش سرعت مشخصی را تضمین نمی‌کنند.

## تنظیمات اختیاری

| متغیر | مقدار پیش‌فرض | کاربرد |
| --- | --- | --- |
| `PRECOMPUTE_ENABLED` | `true` | پیش‌تولید پاسخ و خلاصه پس از رونویسی؛ ممکن است مصرف API را افزایش دهد. |
| `AI_MAX_CONCURRENCY` | `8` | حداکثر درخواست همزمان به مدل. |
| `AI_REQUEST_TIMEOUT_SECONDS` | `90` | محدودیت زمانی هر درخواست مدل، به ثانیه. |
| `RECORD_CACHE_TTL_SECONDS` | `900` | زمان نگهداری رکوردها در حافظه، به ثانیه. |
| `LOG_TIMINGS` | `false` | ثبت زمان پردازش پیام‌ها بدون متن پیام. |
| `PRIVATE_CHAT_ONLY` | `true` | محدودکردن استفاده به چت خصوصی. |

## دیتابیس و اجرا

ساختار دیتابیس نسخه قدیمی در اولین اجرا مهاجرت داده می‌شود؛ پیش از انتقال از دیتابیس موجود، یک نسخه پشتیبان نگه دارید. رکوردهای قدیمی بدون مالک فقط در چت خصوصی همان کاربر قابل دسترسی‌اند. دیتابیس و کش‌ها حاوی متن‌های کاربران هستند و نباید در مخزن ثبت شوند. کش رمزگذاری‌شده GitHub با توکن ربات محافظت می‌شود؛ تغییر توکن، بازیابی کش قبلی را بدون کلید قبلی ناممکن می‌کند. کش GitHub و اجرای زمان‌بندی‌شده، پشتیبان دائمی و اجرای بدون قطعی تضمین‌شده نیستند.

## آزمایش

```bash
python -m unittest discover -s tests -v
```

این آزمایش‌ها ارتباط تلگرام و گوگل را شبیه‌سازی می‌کنند و جای تست عملی با کلید معتبر، صدای واقعی و `ffmpeg` را نمی‌گیرند. تولید صدا در حال حاضر به متن حداکثر ۸۰۰ نویسه محدود است؛ متن بلندتر با خطای مشخص رد می‌شود و بی‌اطلاع بریده نمی‌شود.
